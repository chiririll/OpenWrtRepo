# OpenWrt package repository

Signed apk repository for OpenWrt (AmneziaWG, zapret), published with GitHub Pages.

- `main` holds sources: `config.yml`, `devices/`, `packages/`, `feeds.yml`, `site/`, `scripts/`, CI.
- `gh-pages` is generated by CI. Do not edit it by hand.
- The landing page is a small Vite project in `site/` (HTML in `src/`, CSS split in `src/styles/`). `site/plugin.js` fills it from `config.yml` and `devices/*.yml`.
- The base URL is `base_url` in `config.yml`.
- Publishing adds a normal commit to `gh-pages` that replaces only the `<version>/` directories built in that run; other versions are untouched.

## Setup once

```sh
# 1. Signing key (keep the private key offline; only the secret goes to GitHub)
mkdir -p ~/.secrets
openssl ecparam -genkey -name prime256v1 -noout -out ~/.secrets/razzmatazz-apk.priv.pem
gh secret set APK_SIGNING_KEY < ~/.secrets/razzmatazz-apk.priv.pem

# 2. Push, run the "packages" workflow, then enable Pages: Settings -> Pages -> Deploy from branch -> gh-pages
```

## Local preview of the landing page

```sh
cd site && npm install && npm run dev   # live preview with hot reload
```

## Run the workflow locally (Docker)

Builds, signs and commits to the **local** `gh-pages` branch. Never pushes. Works with a remote Docker context.

```sh
APK_SIGNING_KEY_FILE=~/.secrets/razzmatazz-apk.priv.pem scripts/local/run.sh [--fresh]
git push --force-with-lease origin gh-pages   # publish manually
```

`--fresh` recreates `gh-pages` as a single commit with only the pinned version. The key must match the one already published in `keys/`.

## Add a device

Create `devices/<name>.yml` (see existing ones). New target/subtarget combos get their own SDK build automatically.

## Unverified
